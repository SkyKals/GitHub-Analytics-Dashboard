# Agent Working Rules

File, directory, and role names must be in English: Planner, Implementer, Reviewer, Integrator. Write documents, comments, statuses, and operational text in English. Preserve technical identifiers in their required syntax.

1. Identify the current role and read its contract: [.ai/Index.md](.ai/Index.md), [.ai/Architecture.md](.ai/Architecture.md), [Planner](.ai/Roles/Planner.md), [Implementer](.ai/Roles/Implementer.md), [Reviewer](.ai/Roles/Reviewer.md), [Integrator](.ai/Roles/Integrator.md).
2. Sources of truth: explicit human decisions define permissions; the instructor's original assignment defines academic requirements; the approved specification defines implementation; tasks define details; code defines actual behavior; architecture describes that behavior; review defines the verified state. A conflict between the assignment and specification stops work until clarified. Keep architecture aligned with the code and verify the code against the specification.
3. Implement application code only from an approved specification version. Missing local documents, templates, or a status without an explicit permission record do not prove approval. Stop and request document restoration or a human decision.
4. Sequence: Planner → human approval → Integrator prepares the branch → Implementer completes one ready task → human acceptance → authorized Integrator commit. After all tasks: final checks → Reviewer. A failed review returns separate tasks to the Implementer; scope changes return to the Planner and require renewed approval.
5. The Implementer reports and stops with status “Awaiting acceptance.” Moving forward requires explicit permission to continue and dependencies recorded in commits. The Implementer proposes a commit; the Integrator performs it.
6. Repository/branch preparation, commit, push, and merge each require separate explicit permission. One message may accept a task, authorize a specific commit, and authorize continuation if it names every action. Silence, “looks good,” and a general “continue” do not authorize a Git write. Permission to push a branch does not authorize a merge or a push to `main`.
7. Expected project: `SkyKals/GitHub-Analytics-Dashboard`; SSH remote: `git@github-skykals:SkyKals/GitHub-Analytics-Dashboard.git`; university account: `SkyKals`. Before **every** Git write, the Integrator verifies the real root, branch, index/worktree, fetch and push URLs, local `user.name`/`user.email`, effective author/committer including overrides, and SSH authentication as SkyKals. A name/email and SSH alias alone do not prove the account. Before committing, inspect the staged diff and include only approved files. Any mismatch or changed diff stops the operation; do not automatically change configuration, Git trust, ownership, or conflicts.
8. The primary branch is `main`; laboratory branches are `lab-NN`, with only one active at a time. Create a branch from an up-to-date `main` only after approval and with a clean tree; update `main` only by fast-forward. Do not overwrite existing branches. The default merge is `--no-ff`, after a current “Passed” result for the SHA/version and a manual visual check. Force push is prohibited. Do not automatically squash, rebase, delete branches, discard changes, or rewrite history; rollback requires a separately approved `revert`.
9. Record checks and local evidence according to [.ai/Workflow.md](.ai/Workflow.md). An unverified mandatory criterion cannot receive “Passed.” Code changes after review require another review. After a Git operation, report the result, SHA, and tree state; confirm laboratory completion on GitHub.
10. All of `.ai/`, including architecture, is local and excluded from Git. Do not publish it automatically. Skills do not bypass human permissions: automatic commits, worktrees, and Git configuration remain subject to these rules.
11. Use `rtk` for supported CLIs (`git`, `rg`, `npm`, `npx`, `pnpm`, `yarn`, `docker`, `cargo`, `pytest`). Run PowerShell cmdlets directly, never as `rtk Get-Content`, etc. If PowerShell must run through RTK, explicitly invoke `powershell.exe` or `pwsh.exe`.
